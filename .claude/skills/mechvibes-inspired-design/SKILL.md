# Mechvibes-Inspired Design Skill

## 1. Purpose

Establish a reusable design reference inspired by [Mechvibes](https://mechvibes.com/).

The objective is to create interfaces that feel:

- Modern and visually distinctive.
- Playful without looking childish.
- Interactive and engaging.
- Product-focused rather than overly decorative.
- Clean, organized, and easy to navigate.
- Premium while remaining approachable.

Use Mechvibes as design inspiration, not as a template to reproduce.

Do not copy its branding, assets, exact layouts, or proprietary visual identity.

## 2. Design Philosophy

### Product-first storytelling

Every section should communicate a product benefit, demonstrate functionality, or help users take action.

Prioritize:

- Show the product instead of merely describing it.
- Use interactive previews and realistic interface examples.
- Make important features visually understandable.
- Establish a clear visual hierarchy.
- Keep calls to action easy to identify.

### Personality

The overall design should feel:

- Expressive
- Tactile
- Contemporary
- Friendly
- Immersive
- Carefully crafted

Avoid generic SaaS templates, excessive gradients, unnecessary glassmorphism, and layouts that feel generated from a standard component library.

## 3. Visual Direction

### Typography

Use a modern sans-serif typeface.

Typography should establish a strong hierarchy:

| Element         | Direction                |
| --------------- | ------------------------ |
| Hero heading    | Large, bold, expressive  |
| Section heading | Clear and prominent      |
| Body text       | Comfortable and readable |
| Supporting text | Muted, concise           |
| Buttons         | Medium or semibold       |
| Metadata        | Small and subtle         |

Guidelines:

- Use strong headings with intentional line breaks.
- Keep paragraphs relatively short.
- Avoid excessively small text.
- Maintain consistent font weights and line heights.

### Colors

Build a cohesive color system based on the actual product identity.

Define:

- Primary background
- Secondary background
- Surface and elevated surface
- Primary text
- Secondary text
- Accent color
- Border color
- Interactive states
- Success, warning, and error colors

Use contrast to distinguish sections and interactive elements.

Do not introduce random accent colors or use gradients as a substitute for a coherent palette.

### Spacing

Follow a consistent spacing system.

Recommended base scale:

- 4px
- 8px
- 12px
- 16px
- 24px
- 32px
- 48px
- 64px
- 96px

Give important content enough breathing room.

Avoid both overcrowded layouts and excessive empty space without purpose.

### Shapes and surfaces

Use:

- Consistent border radii.
- Subtle borders.
- Carefully controlled shadows.
- Distinct surface levels.
- Consistent button and input dimensions.

Avoid applying rounded corners to absolutely everything.

## 4. Layout and Composition

### Hero sections

Create an impactful first impression.

A good hero section contains:

1. A concise headline communicating the product value.
2. Supporting text explaining the benefit.
3. A primary call to action.
4. A secondary action when appropriate.
5. A strong product visual or interactive preview.

The product demonstration should be a major visual element, not an afterthought.

### Feature sections

Use varied layouts instead of repeating identical cards.

Possible compositions:

- Two-column text and product preview.
- Full-width interactive demonstrations.
- Feature grids.
- Alternating image and text sections.
- Large editorial sections with supporting details.

Each section should have a distinct purpose.

### Discovery and collection sections

For content-heavy interfaces, use visual collections with:

- Clear titles.
- Descriptive metadata.
- Consistent thumbnails.
- Useful filters and categories.
- Visible interaction states.
- Clear navigation.

Cards should communicate useful information without overwhelming users.

### Community and social proof

Use authentic-looking testimonials, ratings, community activity, and user-generated content when available.

Do not fabricate statistics, reviews, or user feedback.

## 5. Interaction Design

Interactions should feel responsive and intentional.

### Hover states

- Buttons should provide visible feedback.
- Cards may subtly elevate or change their surface.
- Navigation items should communicate their active state.
- Interactive previews should indicate that they can be explored.

### Transitions

Use subtle transitions for:

- Hover and focus states.
- Opening and closing panels.
- Tabs and navigation.
- Dropdowns and dialogs.
- Loading and success feedback.

Keep animations short and purposeful.

Avoid excessive motion and distracting animations.

### Product demonstrations

When appropriate, implement interactive previews instead of static mockups.

Examples:

- Clickable keyboard interfaces.
- Live configuration previews.
- Interactive media controls.
- Realistic product settings.
- Editable demonstrations.

Demonstrations must behave consistently with their visual presentation.

## 6. Responsive Design

Design for:

- Desktop
- Tablet
- Mobile

Requirements:

- No horizontal overflow.
- Appropriate typography scaling.
- Adaptable grids and columns.
- Mobile-friendly navigation.
- Comfortable touch targets.
- Properly scaled product previews.
- Consistent spacing across breakpoints.

Do not simply shrink the desktop layout to fit mobile.

Reconsider the composition for smaller screens.

## 7. Accessibility

Always consider:

- Sufficient color contrast.
- Keyboard navigation.
- Visible focus indicators.
- Semantic HTML.
- Accessible form labels.
- Descriptive button labels.
- Reduced-motion preferences.
- Appropriate image alternative text.

Never rely exclusively on color to communicate status.

## 8. Frontend Implementation Standards

When implementing designs:

1. Inspect the existing project structure before making changes.
2. Identify existing design tokens and reusable components.
3. Preserve established architecture and conventions.
4. Reuse components when appropriate.
5. Avoid unnecessary dependencies.
6. Keep components maintainable and focused.
7. Implement real responsive behavior.
8. Ensure interactive elements actually work.
9. Validate the finished implementation in the browser.

Separate:

- Design tokens
- Layout components
- UI components
- Feature components
- Page-level compositions

Do not introduce arbitrary styling values when an existing design token can be reused.

## 9. Design Review Checklist

Before considering a design complete, evaluate:

### Visual quality

- [ ] Clear visual hierarchy.
- [ ] Consistent typography.
- [ ] Cohesive color palette.
- [ ] Balanced spacing.
- [ ] Consistent component styling.
- [ ] Strong product presentation.

### User experience

- [ ] Clear navigation.
- [ ] Understandable calls to action.
- [ ] Logical content organization.
- [ ] Useful interaction feedback.
- [ ] No unnecessary visual distractions.

### Technical quality

- [ ] Responsive across screen sizes.
- [ ] Accessible interactive elements.
- [ ] Reusable components.
- [ ] No broken interactions.
- [ ] No console errors.

## 10. Instructions for Claude

When this skill is activated:

1. Inspect the existing application before proposing a redesign.
2. Study the reference website and identify its relevant visual patterns.
3. Understand the application's users, purpose, and primary workflows.
4. Identify the biggest UX and visual inconsistencies.
5. Propose a cohesive design direction.
6. Establish or improve the design tokens.
7. Improve the actual interface rather than only producing design descriptions.
8. Preserve existing functionality unless a change is justified.
9. Validate the implementation against the design review checklist.

When reviewing an existing interface, prioritize improvements based on impact rather than changing everything unnecessarily.

**Core principle:** Create interfaces that are visually memorable, product-focused, interactive, and genuinely enjoyable to use.
